# COSIA v0.58 Plan: Memory / Skill Store Remodel And Legacy Removal

## Summary

v0.58 remodels memory, skill, and review storage around the current COSIA direction and removes old migration/compatibility layers.

Core rules:
- Version is `0.58.0`.
- Preserving old development memory SQLite/JSONL data is not a goal.
- Runtime does not silently delete old stores. Unsupported old schemas fail with clear reset guidance.
- Memory uses canonical `tier + ownerId` ownership.
- Scope aliases, JSONL queue migration, and queue migration reports are removed.
- Skill uses the global toolbox only.
- Review inbox remains the shared facade for pending memory and skill items.

## Key Changes

### Memory Store Remodel

- Remove `scope`, `legacyScope`, legacy scope aliases, JSONL candidate/promotion queue migration, `.bak` queue migration reports, and migration report handling.
- Keep canonical SQLite columns centered on `tier`, `owner_id`, `kind`, `content`, source/session/agent/run metadata, status, timestamps, and evidence.
- Reject unsupported old SQLite schemas with reset guidance instead of repairing them in place.
- Use policy memory `candidateTiers`, `allowTiers`, and `denyTiers` only.
- Remove `memory add --scope` and documentation for scope aliases.

### Skill Legacy Removal

- Remove agent manifest legacy `skills` and `skillTriggers` fields.
- Remove `SkillMigration`, `skill migrate`, migration formatter, migration tests, and runtime command catalog entry.
- Keep the global skill toolbox:
  - `skills/<skill-id>.md`
  - `skills/<skill-id>.json`
  - `skills/SKILLS.md`
  - agent `preferredSkills`, `blockedSkills`, and `skillWeights`

### Review Boundary Refactor

- Keep `ReviewInboxService` as the memory/skill pending item facade.
- Keep memory candidate promote/discard/conflict behavior in the memory candidate service.
- Keep skill candidate promote/discard behavior in the skill candidate service.
- Split review output formatting into one `review_formatters.ts` module.
- Preserve CLI, REPL, Telegram, and model-facing review semantics.

### CLI / Catalog / Docs Cleanup

- Split memory and skill CLI registration into focused modules while keeping the existing wrapper export.
- Remove legacy commands from the runtime command catalog.
- Update README and plan index with the canonical v0.58 behavior.
- Do not commit private/runtime artifacts.

## Test Plan

- `npm run typecheck`
- `npm test`
- `npm run build`
- `node dist/src/bin.js policy check`
- `node dist/src/bin.js config check`
- `node dist/src/bin.js memory candidate list`
- `node dist/src/bin.js skill candidate list`
- `node dist/src/bin.js review`

Additional checks:
- Canonical memory DB schema supports add/search/show/update/archive/candidate promote/discard.
- Legacy `scope`/`legacyScope` inputs are rejected by schemas and command surfaces.
- `memory add --scope` is unsupported.
- JSONL queue files are ignored and no migration/report files are created.
- Old SQLite schemas fail with reset guidance.
- Agent manifests/templates do not contain legacy `skills` or `skillTriggers`.
- `skill migrate` and `skill.migrate` catalog entries are absent.
- Review inbox still combines memory and skill pending items.

## Assumptions

- v0.58 is a development workspace remodel.
- Old local memory DB/queue data can be cleared manually if needed.
- Runtime does not auto-delete the memory database.
- Scope-based memory ownership is removed.
- Global skill toolbox is the only canonical skill storage structure.
