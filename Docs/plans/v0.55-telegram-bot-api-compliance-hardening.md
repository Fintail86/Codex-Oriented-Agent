# COSIA v0.55 Plan: Telegram Bot API Compliance & Gateway Hardening

## Summary

v0.55의 목표는 Telegram Gateway를 공식 Bot API 운영 규칙에 맞춰 정리하는 것이다.

## Key Changes

- 버전은 `0.55.0`.
- Telegram long polling은 유지한다.
- webhook 충돌은 자동 삭제하지 않고 `check/start` 실패와 명시 복구 명령으로 처리한다.
- `TelegramApiClient.getWebhookInfo()`와 `deleteWebhook({ drop_pending_updates: false })`를 추가한다.
- 새 CLI:
  - `cosia gateway telegram webhook status`
  - `cosia gateway telegram webhook clear --yes`
- Bot API 응답의 `error_code`, `description`, `parameters.retry_after`, `parameters.migrate_to_chat_id`를 파싱한다.
- `retry_after`가 있으면 send 계열 호출에서 1회 대기 후 재시도한다.
- `migrate_to_chat_id`는 자동 auth 변경하지 않고 복구 명령을 안내한다.
- `allowed_updates`는 `["message", "callback_query"]`로 고정하고 status/check에 표시한다.
- callback query는 `answerCallbackQuery`를 best-effort로 먼저 호출한다.
- README에 BotFather privacy mode, `/command@BotName`, webhook, rate-limit guidance를 문서화한다.

## Test Plan

- webhook URL이 비어 있으면 `check/start` 통과.
- webhook URL이 있으면 `check/start` 실패와 `webhook clear --yes` 안내.
- webhook clear without `--yes` makes no remote mutation.
- webhook clear with `--yes` calls `deleteWebhook` with `drop_pending_updates=false`.
- 429 + `retry_after` send call retries once.
- `migrate_to_chat_id` produces guidance without changing auth.
- `getUpdates` always sends `allowed_updates: ["message", "callback_query"]`.
- callback ack failure does not block callback handling.
- token/secret values are not printed.

## Assumptions

- COSIA does not provide webhook server support in v0.55.
- media upload/download, inline query, edited message, chat member update, reactions are out of scope.
