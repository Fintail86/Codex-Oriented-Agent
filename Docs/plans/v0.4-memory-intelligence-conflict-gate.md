# COSIA v0.4 Plan: Memory Intelligence + Conflict Gate

## Summary

Upgrade long-term memory with scored search, visible reference IDs, lifecycle commands, and conflict-blocking candidate promotion.

Version: `0.4.0`.

## Key Changes

### Memory Search Intelligence

- Replace basic search with deterministic scoring.
- Keep scoring in a dedicated function such as `calculateMemoryScore`.
- Search only active, non-expired memories.
- Score factors:
  - exact phrase match
  - normalized token matches
  - importance
  - confidence
  - recency
  - scope/owner match
- Add:

```text
cosia memory search --show-score
```

`REF_MEMORY.md` entries use:

```md
- [mem:abcd1234 score:8.42 project/decision] COSIA v0.4 improves memory ranking.
```

### Safe Schema Migration

`ensureSchema()` must be idempotent:

- `CREATE TABLE IF NOT EXISTS memories`.
- `PRAGMA table_info(memories)`.
- Only `ALTER TABLE ADD COLUMN` when missing.

Add memory columns:

```text
valid_from
valid_until
expires_at
archived_at
archive_reason
replaced_by_memory_id
```

### Memory Lifecycle CLI

Add:

```text
cosia memory show <memory-id>
cosia memory update <memory-id> [...]
cosia memory archive <memory-id> --reason "<reason>"
cosia memory list --all
```

Rules:

- Memory ids accept unique prefixes.
- `update` affects active memories only.
- `archive` soft-deletes by status and archive metadata.
- Default `memory list` shows active only.

### Candidate Conflict Gate

Add:

```text
cosia memory candidate conflicts <candidate-id>
cosia memory candidate promote <candidate-id> --force
cosia memory candidate promote <candidate-id> --replace <memory-id>
cosia memory candidate promote <candidate-id> --merge <memory-id> --content "<merged content>"
```

Conflict detection:

- Normalize text before comparison:
  - lowercase
  - trim
  - special characters to spaces
  - whitespace collapse
- `duplicate`: same normalized content or containment.
- `overlap`: high token overlap.
- `possible_conflict`: same scope/kind/owner family with partial overlap.
- Do not attempt logical contradiction detection.

Promotion rules:

- No conflict: promote normally.
- Conflict: default promote fails.
- `--force`: insert anyway.
- `--replace`: archive old memory and insert new memory.
- `--merge`: update existing memory with user-provided merged content.
- `--replace` and `--merge` are transactional.

### CLI Output

`memory candidate conflicts` prints readable plain text by default:

- conflict type
- target memory id prefix
- scope/kind
- score or overlap
- memory preview
- candidate preview

`--json` gives raw records.

### Policy and Docs

Update policy:

```json
{
  "memory": {
    "promotionConflictPolicy": "block_until_resolved",
    "archivePolicy": "explicit_cli_only"
  }
}
```

## Test Plan

- Idempotent schema migration.
- v0.3 DB upgrades safely.
- `normalizeMemoryText` absorbs case/punctuation/whitespace differences.
- Scoring reflects phrase/token/importance/confidence/recency.
- Archived/expired memories are excluded.
- `REF_MEMORY.md` includes id, score, scope/kind.
- Show/update/archive/list lifecycle commands.
- Conflict detection returns duplicate/overlap/possible conflict.
- Default promote fails on conflict.
- `--force`, `--replace`, and `--merge` work.
- Transaction rollback works on replace/merge failure.
- Formatter produces readable summary and `--json` raw output.

## Assumptions

- No semantic search or vector DB.
- No automatic conflict resolution.
- Archive is soft-delete.
- Audit clear/archive remains out of scope.
