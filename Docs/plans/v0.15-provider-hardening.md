# COSIA v0.15 Plan: Provider Hardening + Disabled OpenAI-Compatible Provider

## Summary

v0.15의 목표는 COSIA의 model provider 계층을 안정화하는 것이다.

- 버전은 `0.15.0`.
- `codex-cli`는 계속 기본 provider다.
- `openai-compatible` provider는 실제 HTTP provider로 구현하되 기본값은 disabled다.
- API key는 저장하지 않고 환경변수에서만 읽는다.
- 실패 원인을 공통 failure reason으로 분리해 status/check/run 에러 메시지를 명확하게 만든다.
- v0.15는 provider 안정화 단계이며 context maintenance는 v0.16으로 유지한다.

## Key Changes

- `POLICY.json`의 `model.providers`에 timeout, structured retry, max prompt chars, API key env, endpoint path를 추가한다.
- provider 공통 failure reason을 추가한다.
- malformed AgentStep JSON 재시도 instruction은 parse error와 malformed output preview를 포함한다.
- `codex-cli` provider는 CLI 없음, auth 실패, timeout, non-zero exit, malformed JSON을 분리한다.
- `openai-compatible` provider는 Node 24 내장 `fetch`를 사용한다.
- API key는 `process.env[apiKeyEnv]`에서만 읽는다.
- HTTP 401/403, 429, non-2xx, network error, timeout, malformed response를 분리한다.
- CLI에 `cosia provider list`, `cosia provider check <provider-id>`를 추가한다.
- README에 provider setup과 failure reason을 문서화한다.

## Test Plan

- disabled provider 요청은 `disabled` reason으로 실패한다.
- unknown provider 요청은 `unknown_provider` reason으로 실패한다.
- provider timeout override가 적용된다.
- prompt가 provider `maxPromptChars`를 넘으면 호출 전 실패한다.
- malformed AgentStep 후 retry instruction에 parse error와 malformed output preview가 포함된다.
- OpenAI-compatible provider는 missing `baseUrl`, `model`, env key를 각각 명확히 실패 처리한다.
- Mocked fetch로 final/tool_call 응답 파싱을 검증한다.
- Mocked fetch로 401/403, 429, non-2xx, network error, timeout, malformed response를 검증한다.
- 기존 v0.14 tests 유지.
