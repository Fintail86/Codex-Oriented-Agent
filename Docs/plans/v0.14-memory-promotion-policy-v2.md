# COSIA v0.14 Plan: Memory Promotion Policy v2

## Summary

v0.14 adds explicit promotion paths between `session`, `agent`, and `core` memory tiers, plus a manual bridge from core memory to skill candidates.

Confirmed decisions:
- Version: `0.14.0`.
- Promotion creates a target record and archives the source record.
- Core-to-skill-candidate does not archive the source core memory.
- Codex amendment candidates remain deferred to v1.0+.
- Conflict checks use deterministic lexical heuristics, not LLM calls or embeddings.

## Key Changes

- Add `cosia memory promote <memory-id> --to-tier agent --owner-id <agent-id> --reason "<reason>"`.
- Add `cosia memory promote <memory-id> --to-tier core --reason "<reason>"`.
- Add `cosia memory promote <core-memory-id> --to-skill-candidate --skill-name "<name>" --reason "<reason>"`.
- Support conflict resolution with `--force`, `--replace <memory-id>`, and `--merge <memory-id> --content "<merged content>"`.
- Store tier promotion history in SQLite and expose it with `cosia memory promotion list --type tier`.
- Support tier promotion revert by archiving the target and restoring the source snapshot.
- Add policy `memory.promotionPaths`.

## Test Plan

- Verify `session -> agent`, `session -> core`, and `agent -> core`.
- Reject reverse paths such as `core -> agent` and `agent -> session`.
- Detect target-tier lexical conflicts.
- Verify `--force`, `--replace`, `--merge`, transaction rollback, and revert.
- Verify core memory can create a pending high-risk skill candidate without archiving source.
- Run `npm run typecheck`, `npm test`, `npm run build`, and `cosia policy check --repair`.

## Assumptions

- Tier promotion is explicit CLI action, not background automation.
- Source archive is the default; `--copy` is out of scope.
- Core memory is not Codex law.
