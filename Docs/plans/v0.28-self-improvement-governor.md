# COSIA v0.28 Plan: Self-Improvement Governor v1

## Summary

v0.28 introduces `SelfImprovementGovernor` as the runtime service that evaluates memory, skill, and tool improvement evidence under policy. It applies only safe automatic improvements and keeps all tool changes recommendation-only.

## Key Decisions

- `runSession()` after-run handling evaluates only candidates created by the current run.
- Backlog processing is handled only through `cosia improve preview/apply/revert/discard`.
- `evaluationHash` identifies the preview item set and decision snapshot; it is not an apply token.
- `apply --yes` always re-evaluates before applying and reports the actual applied set.
- Memory auto-promotion moves under the Governor while keeping existing conservative policy gates.
- Low-risk skill auto-promotion is allowed only when trigger, metadata, size, duplicate, path-safety, and secret checks pass.
- Skill rollback across filesystem and SQLite is best-effort compensation, with `apply_failed` or `revert_failed` evidence when compensation fails.
- Tool improvement creates only recommendations and evidence; it does not edit runtime config, ToolCatalog, or executor code.
- Governor failures are isolated from the main final-answer flow.
- `policySnapshot` and evidence use JSON-safe deep clone with recursive secret-like redaction.

## Public Interfaces

- `cosia improve status`
- `cosia improve preview`
- `cosia improve apply --yes`
- `cosia improve review`
- `cosia improve show <id>`
- `cosia improve revert <id> --reason "<reason>"`
- `cosia improve discard <id> --reason "<reason>"`
