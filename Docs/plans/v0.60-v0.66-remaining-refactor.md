# COSIA v0.60-v0.66 Plan: Remaining Refactor And Legacy Removal

## Summary

The next refactor round prioritizes cleanup over feature expansion. The completed base now includes the typed CLI command catalog, Gateway registry, Telegram hardening, Gateway role authorization, private master CLI parity, memory/skill store remodel, and review formatter split.

The remaining work focuses on:

- provider/default-provider legacy cleanup
- provider auth boundary separation
- test suite split
- runtime domain module split
- deprecated alias removal
- legacy data compatibility removal
- docs/backlog reconciliation

## v0.60 - Refactor Backlog Reconciliation

Goal:
- Update the project-wide refactor backlog to match the current implementation state.
- Move completed CLI, Gateway, memory/skill, and private-master items into completed cleanup.
- Reorder remaining work around provider cleanup, tests, domain splits, alias removal, and legacy data cleanup.

Scope:
- Docs only.
- No code, config, policy, test, or runtime behavior changes.

Verification:
- `git status --short --ignored`

## v0.61 - Test Suite Split

Goal:
- Split `tests/runtime.test.ts` into feature-focused files while preserving behavior.

Target files:
- provider/config
- gateway/Telegram/auth/jobs
- memory/skill/review
- runtime command/catalog
- tool growth/acquisition
- session/context/debug
- policy/Codex amendment

Guardrails:
- Move tests without changing assertions.
- Extract only minimal shared fixtures.
- Keep the total assertion coverage equivalent.

## v0.62 - Provider Legacy Cleanup

Goal:
- Remove or freeze legacy `model.defaultProvider` compatibility as warning/reset guidance only.
- Keep `codex-cli` only as an explicit compatibility provider profile.
- Keep fresh init with no active provider.

Guardrails:
- Do not reintroduce a default provider.
- Do not let Gateway or connector config own provider selection.
- Missing provider should fail with provider profile setup guidance.

## v0.63 - Provider Auth Boundary Refactor

Goal:
- Split provider profile CRUD, auth resolver, token store, and provider runtime creation.
- Keep `openai-codex`, API-key, env, and OpenAI-compatible auth flows behind provider auth handlers.

Guardrails:
- OAuth tokens live only in the private secret store.
- Status/check/debug output must sanitize auth payloads.
- Do not invent or change live OAuth endpoint behavior without official provider documentation.

## v0.64 - Runtime Domain Module Split

Goal:
- Split large runtime files by domain without behavior changes.

Priority:
- memory manager: storage / candidate / promotion / search
- gateway runtime: input routing / job handling / command handling / rendering
- tool acquisition/growth: draft / candidate / test / activation / blueprint
- capability: scan / storage / proposal / normalization

Guardrails:
- Keep public exports stable through wrapper/index files.
- Do not mix module splits with legacy removals.

## v0.65 - Deprecated Alias Removal

Goal:
- Remove deprecated aliases in grouped waves.

Candidates:
- `agent-runtime`
- `--model-provider`
- legacy command trigger pack normal-path remnants
- stale provider/provider-id guidance

Guardrails:
- Replacement commands must already be tested.
- Removed aliases should fail with migration hints where practical.

## v0.66 - Legacy Compatibility Removal Wave

Goal:
- Remove remaining data compatibility shims that are no longer worth preserving in the development workspace.

Candidates:
- legacy session `agentId`
- legacy v0.29 scan id/fact compatibility
- legacy Telegram process lock/read fallback
- old runtime config compatibility paths

Guardrails:
- Do not silently delete runtime data during ordinary commands.
- Fail with reset/recovery guidance when obsolete data shapes are found.
- Local development DB/session/gateway state is not a preservation target.

## Assumptions

- The repo remains the active project; this is not a restart.
- Behavior-preserving refactors and behavior-changing removals are separate commits.
- Private/runtime artifacts remain untracked.
- New features are out of scope unless explicitly required to complete a cleanup boundary.
