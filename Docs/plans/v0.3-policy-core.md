# COSIA v0.3 Plan: Policy Core

## Summary

Move v0.2 hardcoded guardrails into a runtime-enforced Policy Core.

Version: `0.3.0`.

Core idea:

- Policy is not just prompt text.
- Policy is runtime-enforced.
- `POLICY.json` is source of truth.
- `POLICY.md` is the human/model-readable mirror.

## Key Changes

### Policy Files

Add:

```text
codex/POLICY.json
codex/POLICY.md
```

`init` creates both. Existing workspaces can repair missing policy files through `policy check` or re-running `init`.

Minimum policy contents:

- Tool permission and workspace limits.
- Disabled permissions: `destructive`, `network`, `external_send`, `shell`.
- Existing file overwrite approval.
- Require-tools observation tool policy.
- File-inspection policy requiring `read_file`.
- Memory policy: long-term memory writes only through candidate promotion.

### CLI

Add:

```text
cosia policy show
cosia policy check
cosia policy sync
cosia policy audit --session <session-id> --limit <n>
```

### Runtime Enforcement

- `PolicyEngine` returns structured decisions.
- Tool Registry must ask PolicyEngine before execution.
- Denied tools do not run.
- Agent `allowedTools` checks become policy decisions.
- `run` final rejection is recorded as a policy event.
- v0.2 `requireTools` logic moves into PolicyEngine instead of remaining duplicated.

### PromptBuilder

Add `POLICY.md` to prompt order:

1. `SECURITY.md`
2. `POLICY.md`
3. `RULES.md`
4. `SOUL.md`
5. `USER.md`
6. Agent files
7. Session files
8. Memory
9. Current request

### Audit

Create per-session:

```text
sessions/<session-id>/POLICY_AUDIT.jsonl
```

Event shape:

```ts
type PolicyAuditEvent = {
  id: string;
  timestamp: string;
  sessionId: string;
  agentId: string;
  eventType: "tool_decision" | "final_rejection" | "approval_required";
  allowed: boolean;
  ruleId: string;
  reason: string;
  tool?: "read_file" | "write_file" | "search_files";
  permission?: ToolPermission;
  argsSummary?: Record<string, unknown>;
};
```

Rules:

- Do not store tool result bodies in audit logs.
- Mask secret/API-token-like values in `argsSummary`.
- Add run id later if audit readability needs it.

### Workspace Discovery

CLI discovers nearest parent COSIA workspace using:

```text
codex/SECURITY.md
agents/
sessions/
memory/
```

If not found:

```text
COSIA workspace not found. Run `cosia init` or move into a COSIA workspace.
```

## Test Plan

- `POLICY.json` schema valid/invalid.
- `policy sync` regenerates `POLICY.md`.
- `policy check` detects missing/stale mirror.
- Nested directory command finds parent workspace.
- Outside workspace fails clearly.
- Allowed/denied tool decisions are audited.
- Overwrite denial is audited.
- File-inspection final rejection is audited.
- Audit log does not contain file content.
- v0.2 tests remain valid.

## Assumptions

- Network/shell/destructive/external-send tools remain unregistered.
- Policy is runtime logic, not just model instruction.
- JSON policy is source; Markdown policy is mirror.
- Candidate-first self-improvement continues.
