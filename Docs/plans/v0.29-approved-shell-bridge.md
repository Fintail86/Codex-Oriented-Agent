# COSIA v0.29 Plan: Zero-Base Tool Surface + Approved Shell Bridge

## Summary

v0.29 removes Git/NPM dedicated tools from the default active surface and introduces `shell_request` as a preview-only, one-shot, user-approved shell bridge. This is a practical bridge before a long-term governed terminal substrate.

## Key Decisions

- Initial model-facing tools are `read_file`, `write_file`, `search_files`, and `shell_request`.
- Git/NPM/Python/Bun are not default active tools or default blueprints.
- `shell_request` never executes commands directly; it creates a pending shell approval preview.
- Shell approvals are exact-command, exact-cwd, TTL-bound, one-shot records in `memory/longterm.sqlite`.
- Atomic consume uses `UPDATE ... WHERE id = ? AND status = 'pending' ...`; only one caller can execute an approval.
- `pending -> running -> applied/failed` is one-way; failed approvals are never returned to pending.
- Blocked commands can be recorded but cannot execute even with approval.
- High-risk commands require approval-id-bound confirmation in the apply flow.
- Gateway/Telegram shell execution is blocked by default.
- Shell output is capped/redacted for user display; raw stdout/stderr is not stored.
- Shell execution evidence becomes future capability-growth evidence.

## Public Interfaces

- `cosia shell preview --command "<command>" --reason "<reason>"`
- `cosia shell apply <approval-id>`
- `cosia shell cancel <approval-id>`
