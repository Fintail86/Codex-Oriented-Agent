# COSIA v0.53 Plan: Gateway Role Authorization + Tool Access Policy

## Summary

v0.53의 목표는 Telegram에 박혀 있던 사용자 권한 개념을 Gateway 공통 권한층으로 올리고, 외부 커넥터 요청이 LLM 호출 전 deterministic runtime gate를 통과하도록 정리하는 것이다.

## Key Changes

- 버전은 `0.53.0`.
- `unknown != guest`.
- Gateway roles: `guest < admin < master`.
- `master`는 전역 단일 사용자 1명이다.
- `guest/admin`은 `connector + chatId + userId` chat-scoped binding으로 관리한다.
- `/whoami`는 등록 여부와 무관하게 허용한다.
- unknown users are blocked before LLM/provider calls.
- Tool metadata에 `gatewayAccess` policy를 추가한다.
- Gateway-origin runSession만 Gateway role을 ToolContext에 전달한다.

## Public Interfaces

```text
cosia gateway auth allow-chat <connector> <chat-id> [--label <label>]
cosia gateway auth remove-chat <connector> <chat-id>
cosia gateway auth set-master <connector> <user-id> [--label <label>]
cosia gateway auth clear-master
cosia gateway auth set-role <connector> <user-id> <guest|admin> --chat-id <chat-id> [--label <label>]
cosia gateway auth unset-role <connector> <user-id> --chat-id <chat-id>
cosia gateway auth list
cosia gateway auth check <connector> --chat-id <id> --user-id <id> [--chat-type private|group|channel]
```

## Test Plan

- fresh init has empty gateway authorization and no master.
- unknown `/whoami` works without provider call.
- unregistered user cannot natural-chat, slash command, or request tools.
- guest can natural-chat and use guest-allowed tools.
- admin can use read-only slash commands and read-only tools.
- master can use full Gateway surface in allowed chats.
- master in unallowed chat is blocked.
- local CLI/REPL are not affected by Gateway role checks.

## Assumptions

- Gateway authorization is deterministic runtime policy, not LLM interpretation.
- role changes are system-level boundary changes.
