# COSIA v0.13 Plan: Memory Ownership & Lifecycle

## Summary

v0.13의 목표는 기존 8개 `scope` 중심 Memory 모델을 생명주기 기준의 `tier + kind` 모델로 전환하는 것이다.

핵심 방향:
- Canonical memory owner model은 `tier: core | agent | session`.
- `kind`는 검색/표시/위험도 분류용 의미 태그로 유지한다.
- 기존 `scope`는 legacy 입력/마이그레이션 용도로 유지한다.
- 매핑은 lifecycle 기준이다.
  - `session -> session`
  - `agent -> agent`
  - `global/user/codex/project/task/tool -> core`
- 기존 `--scope` CLI는 deprecated alias로 유지하고, 새 표준은 `--tier`.
- v0.13은 tier 구조를 열어두되, 승격 경로 정책은 v0.14에서 구현한다.
- v0.13은 `session -> agent -> core` 같은 선형 승격을 강제하지 않는다.

## Key Changes

### Memory Model

- `MemoryTier = "core" | "agent" | "session"` 추가.
- `MemoryRecord`와 `MemoryCandidateRecord`의 canonical field를 `tier`, `ownerId`, `kind`, `content` 중심으로 전환한다.
- DB는 안전 마이그레이션으로 `memories`, `memory_candidates`에 `tier`, `legacy_scope` 컬럼을 추가한다.
- 기존 `scope` 컬럼은 삭제하지 않고 legacy/backward compatibility용으로 보존한다.
- 기존 row는 deterministic repair한다.
- 새 write는 `tier`를 원본으로 쓰고, `scope`는 호환용 mirror 값으로만 채운다.

### CLI and Compatibility

- 새 표준 명령:
  - `cosia memory add --tier <core|agent|session> --content "..."`
  - `cosia memory list --tier <tier> [--owner-id <id>]`
  - `cosia memory search --query "..." [--tier <tier>] [--owner-id <id>]`
  - `cosia memory update <id> --tier <tier> [--owner-id <id>]`
- 기존 `--scope`는 계속 받되 deprecated warning을 출력한다.
- `--tier`와 `--scope`를 동시에 주면 실패한다.
- agent/session tier는 `ownerId`가 필수이며 존재하는 owner를 요구한다.

### Runtime Behavior

- 모델 `memoryCandidates`는 `tier`를 우선 사용한다.
- legacy candidate가 `scope`만 주면 mapping으로 `tier`를 repair한다.
- candidate owner 기본값:
  - `session`: current session id
  - `agent`: executing agent id
  - `core`: null
- `REF_MEMORY.md` 생성은 core + current session + executing agent memory만 포함한다.
- `REF_MEMORY.md` prefix는 `tier/kind`를 표시한다.

### Lifecycle Hooks

- `agent delete`가 실제 삭제될 때 해당 agent의 active `agent` memory를 soft-archive한다.
- `cosia session archive <session-id> --reason "<reason>"`는 session status를 `archived`로 바꾸고 active `session` memory를 soft-archive한다.
- `session unassign`은 memory를 archive하지 않는다.
- `core` memory는 agent/session lifecycle에 영향받지 않는다.

### Policy and Risk

- `POLICY.json` memory section에 `candidateTiers`, `autoPromotion.allowTiers`, `autoPromotion.denyTiers`를 추가한다.
- 기본 auto promotion은 `session` low-risk/no-conflict만 허용한다.
- `agent`, `core` candidate는 pending review가 기본이다.
- `scope` 기반 policy는 legacy compatibility로 읽는다.

## Test Plan

- 기존 v0.12 tests 유지.
- 기존 `scope` memories와 legacy candidate가 `tier`로 repair된다.
- `memory add/search/list/update`가 `--tier`와 `--owner-id`를 지원한다.
- `--scope project`는 core로 매핑되고 deprecated warning을 낸다.
- `--tier`와 `--scope` 동시 사용은 실패한다.
- run REF memory는 core + current session + executing agent memory만 포함한다.
- `session archive`가 session-tier memory를 archive한다.
- `agent delete --yes --force`가 agent-tier memory를 archive하고 session은 보존한다.
- session candidate는 ownerId가 current session id로 채워진다.
- agent candidate는 ownerId가 executing agent id로 채워진다.
- core/agent candidate는 conservative policy에서 pending review로 남는다.

검증 명령:

```text
npm run typecheck
npm test
npm run build
cosia policy check --repair
```

## Assumptions

- v0.13은 memory ownership/lifecycle 전환만 다룬다.
- Memory promotion path v2는 v0.14에서 다룬다.
- v0.13은 선형 승격 경로를 강제하지 않고, v0.14의 direct promotion 분기를 가능하게 하는 구조만 만든다.
- 기존 `scope`는 즉시 제거하지 않고 deprecated compatibility layer로 둔다.
- `core memory`는 Codex 법전 자체가 아니다.
- 삭제는 계속 soft-archive 우선이며 hard purge는 v0.13 범위 밖이다.
- Agent manifest에는 memory/session 목록을 저장하지 않는다.
