# COSIA v0.22 Plan: Gateway Core + Telegram Remote Console MVP

## Summary

v0.22 adds a Gateway layer so COSIA can be operated from external channels without bypassing the existing runtime, policy, review, and provider boundaries. The first connector is Telegram long polling.

## Scope

- Version `0.22.0`.
- Telegram is a Gateway connector, not a model provider, agent, skill, or tool.
- Bot token is read from `TELEGRAM_BOT_TOKEN`.
- Chat access is restricted by `connectors.telegram.allowedChatIds`.
- Telegram messages route into existing slash commands, hash natural commands, review inbox, and `runSession()`.
- Mutations require preview plus `/apply` or `#적용`.
- Dangerous commands are blocked by default.

## Runtime Files

Gateway state is local-only:

```text
.cosia-gateway/
  telegram/state.json
  telegram/status.json
  telegram/process.lock
  locks/session_<id>.lock
```

`.cosia-gateway/` is ignored by git.

## Reliability Rules

- `getUpdates` uses stored `nextOffset`.
- Offset advances only after a handled update.
- Network failures use exponential backoff.
- Process and session locks are released in top-level `finally` paths.
- SIGINT/SIGTERM request graceful loop shutdown.

## Test Focus

- Policy repair adds Telegram connector defaults.
- Disabled/missing-token/missing-allowlist checks fail clearly.
- Mocked Telegram getMe/getUpdates/sendMessage paths work.
- Unauthorized chats do not reach runtime.
- `/status`, `/sessions`, `/use`, `/new`, `/review`, `/apply` work through the Gateway.
- Session lock failures return busy instead of racing writes.
