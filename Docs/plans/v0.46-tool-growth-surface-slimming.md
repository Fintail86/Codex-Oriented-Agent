# COSIA v0.46 Plan: Tool Growth Surface Slimming

## Summary

v0.46의 목표는 Tool Growth 내부 상태 머신은 유지하되, 일반 사용자가 `scan -> proposal -> draft -> candidate -> test -> approve -> activate`를 직접 관리하는 느낌을 줄이는 것이다.

## Key Changes

- 버전은 `0.46.0`.
- `tool grow`는 normal guided path로 유지한다.
- `tool candidate`, `tool draft`, `capability`, `active`, `blueprint`는 advanced/governance 표면으로 둔다.
- `tool grow --request` 기본 출력은 routine id, 요청, 후보 생성 성공/실패, 상태, 다음 명령 중심으로 정리한다.
- `tool grow show/review --advanced`에서 내부 id와 evidence 요약을 표시한다.
- REPL/Telegram tool growth wording도 routine-centric으로 정리한다.
- archive/compact/purge 기능은 새로 만들지 않고 evidence lifecycle만 문서화한다.

## Test Plan

- `tool grow --request`는 shell approval, command execution, active tool을 만들지 않는다.
- normal output은 routine id와 next action 중심이다.
- `show --advanced`는 scan/proposal/draft/candidate id를 보여준다.
- test/activate는 계속 `--yes` 없이는 실행되지 않는다.
- rejected/cancelled/activated routine은 default review에서 숨고 `--all`로 보인다.

## Assumptions

- v0.46은 UX/surface slimming 단계이며 저장소/상태머신 재설계가 아니다.
