# COSIA v0.27 Plan: Codex Law Minimalism + Runtime Config Split

## Summary

v0.27 keeps `codex/` as the minimal law layer and moves operational settings into `config/`.

Core principle:

- Codex is law.
- Runtime config is operation.
- Runtime config cannot relax Codex law.
- COSIA may propose Codex amendments, but protected Codex source changes require user review and approval through an approved amendment apply flow.
- The user is the approver, not a manual file editor.

## Implementation Scope

- `codex/POLICY.json` becomes law-only.
- `codex/POLICY.md` remains a generated mirror.
- `config/runtime.defaults.json` is tracked.
- `config/runtime.local.json` is ignored.
- `cosia config show`, `cosia config check`, and `cosia config migrate --from-policy` are added.
- Generic `write_file` is blocked from protected Codex source and mirror paths.

## Protected Paths

Source:

- `codex/SECURITY.md`
- `codex/RULES.md`
- `codex/SOUL.md`
- `codex/USER.md`
- `codex/POLICY.json`

Generated mirror:

- `codex/POLICY.md`

## Runtime Config

Merge order:

1. built-in defaults
2. `config/runtime.defaults.json`
3. `config/runtime.local.json`
4. CLI flags

Merge rules:

- object: recursive merge
- array: replace
- primitive: replace
- null: only where the schema permits it

Secrets are environment-only. Config checks warn on secret-like values.

## Migration

`cosia config migrate --from-policy` previews the split.

`cosia config migrate --from-policy --yes` writes:

- law-only `codex/POLICY.json`
- regenerated `codex/POLICY.md`
- safe defaults to `config/runtime.defaults.json`
- personal/runtime values to ignored `config/runtime.local.json`

Migration must be idempotent and validate all output before writing.
