# COSIA v0.32 Plan: Capability-Linked Shell Preview

## Summary

v0.32 links a pending `CapabilityProposal` to a user-provided, one-shot shell approval preview. It does not draft commands, execute automatically, create tool candidates, or register active tools.

## Key Decisions

- `--from-capability` never creates a command by itself.
- The exact command must be provided by the user through `--command`.
- Only pending proposals with `recommendedNextStep = "shell_preview"` can convert.
- Proposal `sourceScanId` must still exist and be fresh at conversion time.
- Shell approval creation and proposal `converted_to_shell` update happen in one SQLite transaction.
- `buildShellApprovalRecord(...)` is a pure helper shared by standalone and capability-linked preview creation.
- The exact command is stored only in the shell approval record, not copied back into the proposal.
- Default reason/effect text uses abstract capability language only.
- Existing linked approvals prevent new approval creation regardless of linked approval status.
- `shell run --from-capability --yes` creates and applies only when there is no linked approval.
- If a linked approval exists, no new command is used and no command is executed.
- Blocked approvals may be recorded but still cannot execute.

## Public Interfaces

- `cosia shell preview --from-capability <proposal-id> --command "<exact command>"`
- `cosia shell run --from-capability <proposal-id> --command "<exact command>" --yes`
- `cosia shell apply <approval-id>`
- `cosia capability show <proposal-id>`
- `cosia shell status`
