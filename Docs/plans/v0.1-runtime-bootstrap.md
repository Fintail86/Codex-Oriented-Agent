# COSIA v0.1 Plan: Runtime Bootstrap

## Summary

Build the first executable TypeScript CLI MVP from an empty Git repository. The runtime must initialize the project, create agents and sessions, run a model provider, execute policy-gated tools, and persist basic SQLite memory.

Initial provider direction:

- Default model provider: Codex CLI provider.
- Auth uses `codex login`; COSIA must not read or store Codex tokens.
- Codex CLI invocation uses read-only sandbox behavior.
- If Codex CLI is unavailable, mock provider may support development, but real Codex provider failures should not silently fall back.

## Key Changes

### Project Bootstrap

- Use npm.
- TypeScript ESM.
- CLI command name: `agent-runtime`.
- Dev runtime: `tsx`.
- Tests: `vitest`.
- CLI parser: `commander`.
- Runtime validation: `zod`.
- SQLite implementation: Node 24 `node:sqlite` `DatabaseSync`.
- No native SQLite npm package.

### Required CLI

```text
agent-runtime init
agent-runtime agent create <agent-id> --template architect
agent-runtime session create --agent <agent-id> --goal "<goal>"
agent-runtime run --session <session-id> --prompt "<prompt>"
agent-runtime memory add --scope <scope> --content "<content>"
agent-runtime memory search --query "<query>"
```

### Runtime Flow

1. Load `session.json`.
2. Load agent manifest.
3. Load `codex/*.md`.
4. Search memory.
5. Regenerate `REF_MEMORY.md`.
6. Build prompt.
7. Ask provider for structured `AgentStep` JSON.
8. If `tool_call`, validate through Policy Engine and Tool Registry.
9. If `final`, print response.
10. Append run summary to `CONTEXT_MEMORY.md`.
11. Append long-term memory candidates to `memory_candidates.jsonl`.

### Tool and Policy Rules

- Register only `read_file`, `write_file`, and `search_files`.
- `read_file`: workspace inside only.
- `search_files`: workspace inside only.
- `write_file`: workspace inside only.
- Existing file overwrite requires CLI approval.
- Destructive/network/external-send/shell permissions exist only as definitions, not executable tools.

### Prompt Order

1. `SECURITY.md`
2. `RULES.md`
3. `SOUL.md`
4. `USER.md`
5. Agent `AGENT.md`
6. Agent `LOCAL_RULES.md`
7. `SESSION_RULES.md`
8. `REF_MEMORY.md`
9. `CONTEXT_MEMORY.md`
10. Current request

### Memory

- Use `memory/longterm.sqlite`.
- Table: `memories`.
- Search: simple keyword `LIKE` style search.
- Long-term memory is explicitly saved by `memory add`.
- Model `memoryCandidates` are not auto-saved; they are queued only.

## Test Plan

- Manifest schema success/failure.
- Session id and `session.json` creation.
- Prompt assembly order.
- Workspace boundary denial for read/write.
- Overwrite approval requirement.
- `search_files` result conversion.
- Memory insert/search.
- `REF_MEMORY.md` generation.

## Acceptance

Manual acceptance:

```powershell
agent-runtime init
agent-runtime agent create architect-agent --template architect
agent-runtime session create --agent architect-agent --goal "Design the runtime MVP"
agent-runtime memory add --scope project --content "This runtime uses Codex / Agent / Session layers."
agent-runtime run --session <created-session-id> --prompt "현재 세션 목표와 관련 메모리를 요약해줘."
```

Done when:

- Codex provider run succeeds.
- `memory/longterm.sqlite` is created.
- `REF_MEMORY.md` is generated.
- `CONTEXT_MEMORY.md` records run summary.
- Outside-workspace writes are denied.
- `npm test` passes.

## Assumptions

- Node 24+ is available.
- User can complete `codex login`.
- SDK provider is deferred.
- `node:sqlite` experimental warning is accepted.
- Memory promotion is not automatic in v0.1.
