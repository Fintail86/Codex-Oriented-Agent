# COSIA v0.2 Plan: Eyes + Memory

## Summary

Give COSIA two practical abilities:

- It must inspect actual workspace state before answering when required.
- It must treat model-proposed memory as reviewable candidates that can be listed, shown, promoted, or discarded.

Version: `0.2.0`.

## Key Changes

### CLI

Add:

```text
cosia run --require-tools
cosia status
cosia session list
cosia session show <session-id>
cosia memory list --limit <n>
cosia memory candidate list|show|promote|discard
```

Keep `agent-runtime` alias, but document `cosia` as the primary command.

### Tool-Use Discipline

- Add `RunOptions.requireTools`.
- If enabled, `final` before any observation tool is rejected.
- Observation tools are only `read_file` and `search_files`.
- `write_file` does not satisfy this requirement.
- Rejection message tells the model to use `read_file` or `search_files`.
- Tool loop remains capped at 5 turns.

### Memory Candidates

Candidate record:

```ts
type MemoryCandidateRecord = {
  id: string;
  status: "pending" | "promoted" | "discarded";
  scope: MemoryScope;
  ownerId?: string;
  kind: string;
  content: string;
  importance: number;
  confidence: number;
  sourceSessionId: string;
  sourceAgentId: string;
  createdAt: string;
  reviewedAt?: string;
  promotedMemoryId?: string;
  discardReason?: string;
};
```

Rules:

- `appendCandidates` adds id, status, source session, and source agent.
- `candidate list` shows pending by default.
- `--all` includes promoted/discarded/legacy candidates.
- `promote` writes to SQLite `memories` and marks candidate promoted.
- `discard` marks candidate discarded with reason.
- Legacy candidates without ids can be displayed as `line:<n>` but cannot be promoted/discarded.

### Prompt and Visibility

- PromptBuilder includes require-tools guidance.
- `CONTEXT_MEMORY.md` records whether tools were used and which tool names ran.
- `REF_MEMORY.md` generation keeps keyword search.

## Test Plan

- Require-tools rejects final before observation.
- Final is allowed after `read_file` or `search_files`.
- `write_file` alone does not satisfy require-tools.
- Candidate append adds id/status/source metadata.
- Candidate promote creates SQLite memory and updates candidate status.
- Candidate discard records status/reason.
- Status/session/memory commands work in empty and initialized workspaces.
- Mock integration covers `search_files -> final`.

## Acceptance

```powershell
cosia status
cosia session list
cosia run --session session_20260517_architect-agent_001 --prompt "현재 구현 상태를 파일을 보고 요약해줘." --require-tools
cosia memory candidate list
cosia memory candidate promote <candidate-id>
cosia memory search --query "구현 상태"
```

## Assumptions

- v0.2 is observation discipline plus memory gate, not full self-improvement.
- Candidate auto-promotion is not enabled.
- Skill improvement and Codex amendment are deferred.
