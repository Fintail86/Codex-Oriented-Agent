# COSIA v0.5 Plan: Governed Memory Promotion + Revert

## Summary

Move memory governance from purely manual review toward conservative automatic promotion with risk classification, conflict checks, reporting, and revert.

This plan superseded the earlier broad self-improvement roadmap by keeping automation focused on memory first.

## Key Changes

### Post-Run Memory Review Notification

After `run`, new memory candidates are reviewed immediately.

Behavior:

- `appendCandidates()` returns new candidate records.
- `runSession()` scans only new candidates for conflicts.
- Final model answer stays clean on stdout.
- Review summary is emitted through `[cosia]` stderr events.
- No automatic promotion in the notification-only phase.

Example:

```text
[cosia] memory review: 2 candidates created
[cosia] memory conflicts: 1 candidate needs review
[cosia] review: cosia memory candidate conflicts b85ee70a
```

Add:

```text
cosia memory candidate review --latest
cosia memory candidate review --pending
```

### Policy-Based Auto Promotion

Policy:

```json
{
  "memory": {
    "autoPromotion": {
      "mode": "conservative",
      "allowRiskLevels": ["low"],
      "requireNoConflict": true,
      "allowScopes": ["project", "session", "task", "tool"],
      "denyScopes": ["codex", "user", "global"],
      "denyKinds": ["security", "policy", "credential", "secret"]
    }
  }
}
```

Modes:

- `manual`: no auto-promotion.
- `conservative`: low-risk and no-conflict only.
- `balanced`: low/medium-risk and no-conflict.
- `strict`: high-risk/conflict always pending.

Default: `conservative`.

### Deterministic Risk Classifier

No LLM call for risk classification.

Use rule-set classifier:

```ts
type RiskLevel = "low" | "medium" | "high";
```

High risk:

- `scope = codex`
- `kind = security | policy | credential | secret`
- secret detector matched
- content implies Codex/POLICY/SECURITY or permission changes

Medium risk:

- `scope = user | global`
- `kind = decision | preference | architecture`
- content affects long-term structure or working method

Low risk:

- `scope = project | session | task | tool`
- `kind = note | observation | command`
- no secret-like content
- no conflict

### Secret Detection

Use layered regex, not simple `includes`.

Detect:

- OpenAI-style key
- AWS key
- JWT
- assignment patterns: `password`, `token`, `api_key`, `secret`, `private_key`
- bearer token
- PEM private key
- conservative keywords: `token`, `credential`, `password`, `secret`, `api key`

Secret-like candidates:

- always high-risk
- remain pending
- show redacted preview in summaries

### Auto Promotion Records and Revert

Store:

```text
memory/auto_promotions.jsonl
```

Record:

```ts
type AutoPromotionRecord = {
  id: string;
  candidateId: string;
  promotedMemoryId: string;
  runId?: string;
  sessionId: string;
  agentId: string;
  riskLevel: RiskLevel;
  reasons: string[];
  policyMode: "manual" | "conservative" | "balanced" | "strict";
  createdAt: string;
  revertedAt?: string;
  revertReason?: string;
};
```

Add:

```text
cosia memory promotion list
cosia memory promotion show <promotion-id>
cosia memory promotion revert <promotion-id> --reason "<reason>"
```

Revert:

- archive auto-created memory
- return candidate to pending or reverted state
- record revert metadata

### Batch Review

Add:

```text
cosia memory candidate promote --all-low-risk --yes
cosia memory candidate discard --all-low-risk --reason "<reason>" --yes
```

Rules:

- conflict candidates excluded
- high-risk/secret-like excluded
- summary first, `--yes` required for mutation

## Test Plan

- Review summary prints after run.
- Conflict does not fail final answer.
- Classifier sorts low/medium/high deterministically.
- Secret patterns become high-risk.
- Redacted previews for secret-like content.
- Conflict candidate never auto-promotes.
- Conservative mode auto-promotes only low-risk/no-conflict.
- Auto promotion record is written.
- Revert archives memory and restores candidate state.
- Batch commands exclude unsafe candidates.

## Assumptions

- Automatic promotion starts with memory only.
- Balanced mode is opt-in.
- Replace/merge remain manual.
- Skill and Codex amendment automation are deferred.
