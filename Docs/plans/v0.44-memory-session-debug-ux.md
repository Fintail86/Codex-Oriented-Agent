# COSIA v0.44 Plan: Memory / Session / Debug UX

## Summary

v0.44의 목표는 COSIA의 continuity layers를 사용자와 유지보수자가 헷갈리지 않게 정리하는 것이다.

## Key Changes

- 버전은 `0.44.0`.
- storage engine/schema는 바꾸지 않는다.
- `CONTEXT_MEMORY.md`는 working context, `SESSION_SUMMARY.md`는 compact continuity, long-term memory는 reviewed durable memory, `debug/` 파일은 diagnostic record로 구분한다.
- `cosia session debug <session-id>` 계열을 추가한다.
- `session show`, `session context status`, `session prompt` 출력 설명을 정리한다.
- status/doctor wording에서 long-term memory count와 session context health를 분리한다.

## Public Interfaces

```text
cosia session debug <session-id>
cosia session debug <session-id> --part metadata
cosia session debug <session-id> --part user-message
cosia session debug <session-id> --part prompt
cosia session debug <session-id> --part all
cosia session debug <session-id> --part prompt --max-chars <n>
```

## Test Plan

- debug record missing message is clear.
- run/chat writes debug metadata, last user message, last prompt.
- prompt/all output applies max chars and truncation marker.
- debug command cannot read outside session-local debug path.
- context compact behavior remains unchanged.

## Assumptions

- debug prompt data is diagnostic-only and not auto-promoted to memory.
