# COSIA v0.56 Plan: CLI Command Catalog Refactor

## Summary

v0.56 reduces drift between the real COSIA CLI and the model-facing command catalog. The catalog remains a one-to-one index of CLI command paths, but model execution now goes through typed command specs and an argv planner instead of ad-hoc string templates.

Core principles:

- CLI commands and model-facing `commandId` entries stay aligned.
- LLMs never provide shell strings, raw CLI strings, or arbitrary argv.
- Runtime lookup remains tag-based command navigation, not a natural-language command translator.
- Dangerous and system-boundary commands stay visible in the catalog but blocked from model-facing execution.
- Deprecated aliases remain for a later removal wave.

## Key Changes

- Add typed `CliCommandSpec` metadata with `commandId`, `commandPath`, `cliDisplay`, `description`, `safety`, `tags`, `argsSchema`, `modelCallable`, `modelExecutionMode`, and approval metadata.
- Replace exported `argvTemplate` with typed `argvPlan` tokens:
  - literal command segment
  - required/optional positional arg
  - required/optional option value
  - boolean flag
- Route `cosia_runtime_command` through `buildCliArgv(spec, args)` as the only argv generation path.
- Add Commander command tree coverage tests so public CLI paths are represented in the catalog.
- Keep `cosia_cli_command_lookup` as tag-based candidate lookup only.
- Remove the old `parseRuntimeHashCommand` phrase parser from the runtime command catalog.
- Keep trigger packs as legacy/debug metadata, not normal execution.
- Replace personal-looking Telegram fixture values in tests with fixture constants.

## Safety

- Catalog presence does not imply model execution permission.
- Gateway guest remains blocked from lookup/runtime command tools.
- Gateway admin can run only read-only model-callable commands.
- Private direct master chat may run non-system local CLI commands through the existing controlled path.
- `system_boundary`, `dangerous`, shell, pending apply/cancel, provider auth, connector auth, and Codex apply commands remain blocked from model-facing execution.

## Test Plan

- `npm run typecheck`
- `npm test`
- `npm run build`
- `node dist/src/bin.js gateway status`
- `node dist/src/bin.js provider profile check`
- `node dist/src/bin.js policy check`
- `node dist/src/bin.js config check`

Targeted checks:

- All Commander public command paths are represented by `CliCommandSpec.commandPath`.
- Every `commandId` is unique and not a CLI string.
- `buildCliArgv` handles required args, optional args, option values, and boolean flags.
- `memory.search` executes as `memory search --query <query>`.
- Lookup returns tag-based candidates without phrase-specific direct mapping.
- Deprecated aliases continue to work.

## Assumptions

- v0.56 is a structural refactor, not a user-facing command behavior change.
- Full deprecated alias removal is v0.57+ work.
- The command catalog is an LLM reference and constrained execution surface, not an intent router.
