# COSIA v0.27.2 Plan: Git Tools as Bundled Extensions

## Summary

`git_status`, `git_diff`, and `git_log` move out of concrete Codex law tool configuration and become bundled read-only extension tools.

Core rule:

- Codex law defines permission and security boundaries.
- ToolRegistry defines each tool's permission and workspace boundary.
- Runtime config can only enable or disable bundled tools.
- Runtime config cannot redefine permission, workspace, command, or security behavior.

## Changes

- Remove Git tools from `codex/POLICY.json.tools`.
- Keep `read_file`, `write_file`, `search_files`, `npm_test`, and `npm_typecheck` in policy for now.
- Add `config/runtime.defaults.json.tools.bundled.git_status/git_diff/git_log`.
- Add strict bundled tool config: `{ enabled: boolean }` only.
- Reject or report config issues for wrong enabled types, metadata override attempts, and unknown bundled ids.
- Update PolicyEngine decision order:
  1. ToolRegistry definition
  2. agent `allowedTools`
  3. bundled runtime config enabled
  4. `disabledPermissions`
  5. permission/workspace/security rules
- Keep default/architect agent Git tools in `allowedTools`.
- Regenerate `POLICY.md` with `Core Runtime Tools` and no Git tools listed as core policy tools.
- Bump version to `0.27.2`.

## Follow-Up Debt

- Re-evaluate `npm_test` and `npm_typecheck` as bundled project-check extensions.
- Consider a `project_check` or `controlled_command` permission class for npm tools.
- Add future output security scan/redaction for `git_diff`.
- Remember: read-only does not mean safe-to-display.
