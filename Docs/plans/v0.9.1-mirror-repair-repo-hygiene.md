# COSIA v0.9.1 Plan: Mirror Repair + Repo Hygiene

## Summary

Polish generated mirrors and clean repository tracking boundaries.

Version: `0.9.1`.

## Key Changes

### Policy Mirror Repair

Add:

```text
cosia policy check --repair
```

Behavior:

- Validate `POLICY.json`.
- Detect missing/stale `POLICY.md`.
- Regenerate `POLICY.md` from JSON when `--repair` is used.
- `run`/`chat` auto-sync stale `POLICY.md` before prompt assembly.
- Deterministic local generation only; no LLM usage.

### Skill Mirror Check

Add:

```text
cosia skill check --agent <agent-id>
cosia skill check --agent <agent-id> --repair
```

Checks:

- Manifest skill entries have files.
- `SKILLS.md` matches generated mirror.
- Triggerless skill shows manual-only warning.
- Orphan skill files warn only.

Repair:

- Regenerate `SKILLS.md` only.
- Do not alter manifest, skill files, or orphan files.

### Repo Hygiene

Update `.gitignore`:

```text
memory/*
sessions/*
```

Remove already-tracked runtime state from git index without deleting local files:

```powershell
git ls-files sessions memory
git rm --cached -- <tracked-runtime-files>
```

Keep project config trackable:

- source
- policy
- agent definitions
- promoted skill files
- tests
- docs

Do not commit runtime artifacts:

- SQLite DB
- queue `.bak`
- migration reports
- session context
- audit logs
- prompt manifests

### Docs

README documents:

- `POLICY.json` is source of truth.
- `POLICY.md` and `SKILLS.md` are generated mirrors.
- Runtime state should stay out of git.

## Test Plan

- Stale policy mirror is detected.
- `policy check --repair` repairs mirror.
- `run/chat` auto-sync stale policy mirror.
- Skill check detects stale mirror.
- Skill check repair regenerates mirror.
- Triggerless skill warnings show.
- Orphan skill file warning does not delete.
- Runtime artifacts remain ignored.
- v0.9 tests continue to pass.

## Assumptions

- Mirror repair is deterministic and token-free.
- Existing local runtime state is preserved.
- Hash/mtime optimization is deferred; string compare is enough.
