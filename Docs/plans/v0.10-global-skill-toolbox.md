# COSIA v0.10 Plan: Global Skill Toolbox Refactor

## Summary

Correct the v0.9 skill model: skills are not agent-owned; they are global tools that agents select according to preferences.

Version: `0.10.0`.

## Key Changes

### Global Skill Toolbox

Canonical structure:

```text
skills/
  SKILLS.md
  <skill-id>.md
  <skill-id>.json
```

Metadata:

```ts
type SkillMetadata = {
  id: string;
  name: string;
  description?: string;
  triggers: string[];
  riskLevel: "low" | "medium" | "high";
  createdAt: string;
  updatedAt: string;
  sourceCandidateId?: string;
  suggestedByAgentId?: string;
};
```

`skills/SKILLS.md` is generated mirror/index.

### Agent Manifest Preferences

Agents no longer own skills.

Manifest fields:

```ts
type AgentManifest = {
  preferredSkills: string[];
  blockedSkills: string[];
  skillWeights?: Record<string, number>;
};
```

Rules:

- `preferredSkills`: +3 bonus.
- `blockedSkills`: automatic and manual selection denied.
- `skillWeights`: 0..5 score bonus.
- Legacy `skills` and `skillTriggers` are read for compatibility only.

### Skill Candidate Flow

- `agentId` in skill candidates becomes `suggestedByAgentId`.
- Promotion writes global skill md/json.
- Promotion does not automatically mutate agent manifest.
- Optional:

```text
cosia skill candidate promote <id> --yes --prefer-for <agent-id>
```

Duplicate global skill id fails.

### PromptBuilder Selection

Selection algorithm:

1. Exclude blocked skills.
2. Score triggers:
   - current request phrase: +5
   - session goal phrase: +2
3. Apply agent preference:
   - preferred: +3
   - weight: +0..5
4. Sort by score.
5. Tie-break:
   - preferred first
   - `createdAt` ascending
   - `skillId` alphabetically
6. Apply skill budget.

Manual selection:

```text
cosia run --session <id> --prompt "..." --skill <skill-id>
cosia chat --session <id> --skill <skill-id>
/skills use <skill-id>
```

Manual selection still respects `blockedSkills`.

### CLI

Global skill commands:

```text
cosia skill list
cosia skill show <skill-id>
cosia skill sync
cosia skill check [--repair]
cosia skill candidate list|show|promote|discard|export
```

Agent preference commands:

```text
cosia skill list --agent <agent-id>
cosia skill prefer <skill-id> --agent <agent-id> [--weight <0-5>]
cosia skill unprefer <skill-id> --agent <agent-id>
cosia skill block <skill-id> --agent <agent-id>
cosia skill unblock <skill-id> --agent <agent-id>
```

Explain command:

```text
cosia skill select --agent <agent-id> --prompt "<prompt>" [--goal "<goal>"] [--skill <skill-id>] --explain
```

Output is compact table/list.

### Legacy Migration

Add:

```text
cosia skill migrate --agent <agent-id>
cosia skill migrate --agent <agent-id> --yes
```

Rules:

- Preview by default.
- Copy legacy agent-local skills to global `skills/`.
- Convert legacy triggers into metadata triggers.
- Preserve original files.
- Add migrated skill to agent `preferredSkills`.

## Test Plan

- `init` creates global `skills/`.
- Promote creates global md/json.
- Preview does not mutate.
- `--prefer-for` updates manifest.
- prefer/unprefer/block/unblock work.
- Blocked skill denied in auto and manual selection.
- Trigger match is global, not agent-local.
- Weight and preference affect score.
- Tie-break is deterministic.
- Triggerless skill is manual-only.
- Explain output is readable.
- Stale mirror repair works.
- Legacy migration preview/apply works.

## Assumptions

- Skill metadata is separate JSON, not MD frontmatter.
- Visual explorer is out of scope.
- Automatic skill promote remains out of scope.
