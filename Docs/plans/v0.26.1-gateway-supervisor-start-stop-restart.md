# COSIA v0.26.1 Plan: Gateway Supervisor Start/Stop/Restart

## Summary

Gateway is promoted from Telegram-specific execution to a top-level foreground supervisor.
Users should normally remember:

```text
cosia gateway start
cosia gateway status
cosia gateway stop
cosia gateway restart
```

Telegram remains the only supported connector in v0.26.1, but it is now treated as a connector under Gateway rather than as Gateway itself.

## Key Decisions

- Version: `0.26.1`.
- `gateway start` starts enabled connectors from `POLICY.json`.
- `--connector telegram` narrows the start/restart target to Telegram.
- `--model-provider` selects the COSIA model provider used for gateway chat messages.
- `gateway stop` writes a cooperative stop request instead of force-killing a process.
- `gateway restart` waits for the process lock to disappear before starting again.
- Top-level process lock: `.cosia-gateway/process.lock`.
- Stop request: `.cosia-gateway/control/stop.json`.
- Telegram-specific commands remain as low-level check/debug commands.

## Safety

- Stop requests are cleaned during graceful shutdown.
- Stale stop requests are ignored/removed when no live gateway lock exists.
- `gateway unlock --stale-only` removes stale top-level locks only.
- Telegram mutations still require preview plus `/apply` or `#적용`.
- Dangerous commands remain blocked in Telegram.
