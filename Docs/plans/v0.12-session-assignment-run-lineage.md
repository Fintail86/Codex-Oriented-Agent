# COSIA v0.12 Plan: Session Assignment & Run Lineage

## Summary

v0.12의 목표는 세션을 agent 소유물이 아니라 전역 작업 단위로 정리하는 것이다. Agent는 세션을 소유하지 않고, 세션에 배정되거나 특정 run을 실행한다.

구현 전 `.gitignore`의 `Docs/` 추가는 별도 커밋 `chore: ignore local planning docs`로 먼저 정리한다. `Docs/` 내부 플랜 문서는 로컬 세션 인계용이므로 커밋하지 않는다.

## Key Changes

### Session Model

`SessionMetadata`를 `assignedAgentId` 중심으로 전환한다.

```ts
type SessionMetadata = {
  id: string;
  assignedAgentId: string | null;
  status: "active" | "completed" | "archived";
  goal: string;
  createdAt: string;
  updatedAt: string;
};
```

- 기존 `session.json`의 `agentId`는 legacy로 읽고 `assignedAgentId`로 repair한다.
- 신규 코드 내부 참조는 `session.assignedAgentId`를 사용한다.
- legacy `agentId`는 새로 쓰지 않는다.

### Session IDs and Assignment

새 세션 id는 agent id를 포함하지 않는다.

```text
session_YYYYMMDD_001
```

- `session create --agent <agent-id> --goal <goal>`은 `assignedAgentId`를 설정한다.
- `session create --goal <goal>`은 policy default agent를 `assignedAgentId`로 사용한다.
- `session assign <session-id> --agent <agent-id>`는 존재하는 agent만 배정한다.
- `session unassign <session-id>`는 `assignedAgentId: null`로 만든다.
- `session list --agent <agent-id>`는 배정된 세션만 필터링한다.
- `agent sessions <agent-id>`는 해당 agent에 배정된 세션을 출력한다.

### Run Lineage

`run/chat --agent <agent-id>`를 추가한다.

- `--agent`가 있으면 해당 run의 실행 agent로 사용한다.
- `--agent`는 세션의 `assignedAgentId`를 자동 변경하지 않는다.
- `--agent`가 없으면 `assignedAgentId`를 사용한다.
- 둘 다 없으면 `session assign` 또는 `run --agent` 힌트와 함께 실패한다.
- 실행 agent는 반드시 존재해야 한다.

기록 대상:

- policy audit event의 `agentId`
- prompt manifest의 실행 `agentId`
- `CONTEXT_MEMORY.md` run entry의 `Agent: <agent-id>`
- memory/skill candidates의 `sourceAgentId`

### Agent Delete and Orphan Sessions

- Agent 삭제는 세션을 삭제하지 않는다.
- `AgentManager.sessionReferences()`는 `assignedAgentId` 기준으로 찾는다.
- 삭제된 agent를 가리키는 세션은 orphan 상태로 표시한다.
- orphan 세션 복구는 `cosia session assign <session-id> --agent <agent-id>`로 한다.

### Docs and Version

- 버전은 `0.12.0`.
- README의 command list와 runtime rules를 `assignedAgentId`, run lineage, orphan session 기준으로 갱신한다.

## Test Plan

- 기존 legacy session with `agentId`가 `assignedAgentId`로 repair된다.
- 새 session id가 agent id를 포함하지 않는다.
- `session create --goal`이 default agent를 배정한다.
- `session create --agent`가 지정 agent를 배정한다.
- `session assign`과 `session unassign`이 `session.json`을 갱신한다.
- `session list --agent`와 `agent sessions`가 올바르게 필터링한다.
- `run --agent`는 실행 agent만 바꾸고 세션 배정은 바꾸지 않는다.
- `chat --agent`도 같은 규칙을 따른다.
- assigned agent가 missing인 세션은 list/show에서 orphan으로 표시된다.
- agent 삭제 후 세션은 유지된다.
- orphan 세션은 `session assign`으로 복구된다.
- audit, prompt manifest, context entry, memory candidates, skill candidates가 실행 agent id를 기록한다.
- 기존 v0.11 tests는 유지된다.

검증 명령:

```text
npm run typecheck
npm test
npm run build
cosia policy check --repair
```

## Assumptions

- `.gitignore` 변경은 v0.12 구현 전에 별도 커밋한다.
- `run/chat --agent`는 one-run override이며 세션 배정을 바꾸지 않는다.
- 세션 목록은 agent manifest에 저장하지 않는다.
- Agent 삭제는 세션이나 메모리를 삭제하지 않는다.
- Session memory tier 개편은 v0.13에서 한다.
- Memory promotion policy v2는 v0.14에서 한다.
