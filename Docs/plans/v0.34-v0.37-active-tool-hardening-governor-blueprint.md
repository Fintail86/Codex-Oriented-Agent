# COSIA v0.34-v0.37 Plan: Active Tool Hardening, Governor Integration, Learned Blueprint

## Summary

v0.34-v0.37 hardens the v0.33 active tool acquisition path instead of replacing it. The sequence covers activation safety, command-adapter execution evidence, Governor candidate recommendations, and learned local blueprints.

## v0.34: Active Tool Activation Hardening

- Activation is preview-only by default; `--yes` is required to apply.
- Activation preview shows candidate, target tool, target agent, executor, permission, exposure, latest passed test, allowedTools before/after, and expected effective visibility.
- Activation remains per-agent.
- Activation failure keeps candidate status `approved`.
- Activation failure creates `activation_failed` or `rollback_failed` evidence.
- Compensation attempts deactivate/delete active records and restore agent manifest snapshots.
- Deactivation sets active record `deactivated`, removes target agent allowlist entries, verifies effective visibility removal, and records evidence.
- Effective model visibility requires active record, active status, model exposure, target agent allowlist, and policy permission.
- `ts_module` activation remains blocked at CLI and service layers.

## v0.35: Command Adapter Runtime Hardening

- `command_adapter` is a fixed process adapter, not arbitrary shell.
- Shell strings, model-provided args, interpolation placeholders, and non-`workspace_root` cwd policies are rejected.
- Execution uses fixed executable and fixed args only.
- Env is restricted to a minimal allowlist.
- Secret-like env is not passed and is not stored.
- Execution evidence stores exit code, duration, redacted summary, and failure kind only.
- Raw stdout/stderr is not persisted.
- Failure kinds include `spawn_failed`, `timeout`, `non_zero_exit`, `output_handling_failed`, and `policy_denied`.
- Active plans are immutable; plan changes require new candidates.

## v0.36: Governor Tool Candidate Integration

- Governor can detect repeated shell approval patterns.
- Governor can connect capability proposal and shell approval evidence.
- Governor can create deduped tool candidate recommendation evidence.
- Governor cannot activate tools, execute shell, apply executor code, edit runtime config, edit ToolCatalog, or relax policy.
- Recommendation dedupe uses capability family, shell command fingerprint, source agent, source session, and suggested target tool id.

## v0.37: Learned Local Blueprint

- Successful repeated active command-adapter tools can produce learned local blueprints.
- Blueprint creation requires successful execution threshold, low recent failure rate, safe permission, and no secret-like evidence.
- Learned blueprint stores capability family, executor kind, sanitized immutable command adapter plan, permission, test plan, rollback note, source active tool ids, and evidence summary.
- Learned blueprints are workspace-local evidence artifacts, not built-in blueprints.
- Learned blueprints do not activate tools automatically.
- Export/import and shared blueprint packs remain future work.
