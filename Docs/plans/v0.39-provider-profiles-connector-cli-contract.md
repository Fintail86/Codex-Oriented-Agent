# COSIA v0.39 Plan: Provider Profiles + Connector CLI Contract

## Summary

v0.39의 목표는 개발 중 하드코딩된 기본 provider 관성을 제거하고, 사용자가 CLI로 등록하고 선택한 provider profile 구조로 전환하는 것이다.

핵심 원칙:

- fresh init에는 active provider가 없다.
- `codex-cli`는 기본 provider가 아니며, 명시 profile로만 사용한다.
- Telegram은 Gateway connector이며 model provider를 소유하지 않는다.
- Gateway는 active provider profile을 사용한다.
- connector CLI는 `enable/disable/set/unset/list/check` 패턴으로 통일한다.
- secret 값은 출력, check/status, audit/evidence에 노출하지 않는다.

## Key Changes

- `ProviderProfile`과 `ModelConfig`를 도입한다.
- provider resolution 순서는 CLI override, `model.activeProviderProfile`, missing failure다.
- legacy `model.defaultProvider`는 자동 fallback으로 쓰지 않고 warning/repair 대상으로 둔다.
- API key는 hidden prompt로 받고 `config/secrets.private.json`에만 저장한다.
- `--oauth`는 COSIA에 OAuth token을 저장하지 않는다.
- private runtime/secret config는 `config/runtime.private.json`, `config/secrets.private.json`로 정리한다.

## Public Interfaces

```powershell
cosia provider profile add codex --provider codex-cli --oauth
cosia provider profile add openrouter --provider openrouter --api-key --model <model-id>
cosia provider profile add openai --provider openai-compatible --api-key --base-url <url> --model <model-id>
cosia provider profile add openrouter-env --provider openrouter --api-key-env <ENV_NAME> --model <model-id>

cosia provider profile use <name>
cosia provider profile list
cosia provider profile show <name>
cosia provider profile check [<name>]
cosia provider profile remove <name>
```

Telegram setup:

```powershell
cosia gateway telegram enable
cosia gateway telegram set chat-id <chat-id>
cosia gateway telegram set token
cosia gateway telegram check
cosia gateway start
```

## Test Plan

- fresh init creates no active provider profile.
- gateway start without active provider fails with setup guidance.
- provider profile list/show/check never prints secrets.
- `provider profile use <name>` changes active profile.
- legacy `model.defaultProvider` is not used as fallback.
- Telegram token is stored only in private secret store.
- Telegram config does not contain provider profile/provider id/default provider.

## Assumptions

- `codex-cli` remains supported only through explicit profile.
- Telegram remains a connector and never owns provider selection.
- private/runtime files are user-specific ignored artifacts.
