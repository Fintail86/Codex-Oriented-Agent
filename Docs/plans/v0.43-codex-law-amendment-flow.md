# COSIA v0.43 Plan: Codex Law Amendment Flow

## Summary

v0.43의 목표는 `codex/*` 보호 법전 파일을 일반 `write_file` 수정이 아니라 전용 Codex amendment preview/apply flow로 다루는 것이다.

## Key Changes

- 버전은 `0.43.0`.
- `codex_amendments` ledger를 추가한다.
- `CodexAmendmentLedger` runtime service를 추가한다.
- protected Codex write attempt는 파일을 변경하지 않고 amendment preview/guidance를 반환한다.
- `codex/POLICY.md`는 generated mirror이므로 직접 amendment target으로 받지 않는다.
- `codex/POLICY.json` apply 성공 시 `PolicyManager.syncMarkdown()`으로 mirror를 재생성한다.

## Public Interfaces

```text
cosia codex show [--path <protected-path>]
cosia codex check
cosia codex amendment list [--all]
cosia codex amendment show <id>
cosia codex amendment propose --path <path> (--content <text> | --content-file <file>) --reason "<reason>"
cosia codex amendment apply <id> --yes
cosia codex amendment reject <id> --reason "<reason>"
cosia codex amendment cancel <id> --reason "<reason>"
```

## Test Plan

- direct `write_file` to protected Codex paths is blocked.
- proposal stores target path, previous hash, proposed hash, reason, pending status.
- secret-like proposed content is rejected before ledger creation.
- apply without `--yes` does not write files.
- stale hash blocks apply.
- reject/cancel preserve evidence and do not modify files.
- conversational approval alone does not apply amendments.

## Assumptions

- v0.43 is Codex law only.
- agent behavior file amendment is future work.
