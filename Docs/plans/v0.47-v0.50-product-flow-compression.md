# COSIA v0.47-v0.50 Plan: Product Flow Compression

## Summary

v0.47 이후 목표는 내부 시스템을 전부 더 고도화하는 것이 아니라, COSIA를 경량 Codex-CLI-like provider-neutral runtime으로 압축하는 것이다.

핵심 원칙:

- 일반 사용자는 capability/proposal/draft/candidate/evidence state machine을 몰라도 된다.
- normal UX는 `init`, `provider setup`, `start/chat/run`, `status/doctor`, `memory`, `approve/apply/cancel`, gateway connector 중심이다.
- tool growth, active tool, blueprint, governed terminal, legacy migration detail은 advanced/governance/debug 표면으로 둔다.

## v0.47 Normal Product Surface Compression

- README Quick Start를 provider setup부터 chat까지 이어지는 흐름으로 재정렬한다.
- `cosia --help`, `cosia tool list`, chat `/help`에서 advanced 명령을 덜 전면에 둔다.
- normal/advanced/debug 명령 분류표를 현재 구현 기준으로 갱신한다.

## v0.48 First-Run And Recovery UX

- no active provider, invalid provider, missing Telegram token/chat id, stale gateway lock, no active session 메시지를 통일한다.
- 실패 메시지는 바로 실행 가능한 복구 명령을 포함한다.
- `cosia start`, `config check`, `provider profile check`, `gateway telegram check`, `status` recovery wording을 맞춘다.

## v0.49 Approval UX Unification

- pending approval 상태를 한 곳에서 보는 normal command를 설계/구현한다.
- Telegram/REPL에서 plain approval은 적용하지 않고 명시 apply command를 안내한다.
- Codex law, shell approval, file preview, review promotion/discard 흐름을 일관되게 만든다.

## v0.50 Memory And Continuity As Product Core

- session context, summary, long-term memory, debug record UX를 정리한다.
- `memory`와 `session` 명령 안내를 장기 프로젝트 기억 중심으로 재배치한다.
- provider switching 후에도 continuity가 유지된다는 점을 README/status에서 명확히 한다.

## Assumptions

- 기존 내부 기능은 삭제하지 않는다.
- 다음 라운드의 중심은 기능 추가보다 사용 흐름 압축이다.
