# COSIA v0.15.1 Plan: OpenRouter Provider Preset

## Summary

v0.15.1의 목표는 v0.15의 `openai-compatible` provider를 기반으로 OpenRouter API를 실전 provider로 쉽게 사용할 수 있게 만드는 것이다.

- 버전은 `0.15.1`.
- `codex-cli`는 계속 기본 provider다.
- 새 provider id `openrouter`를 추가한다.
- `openrouter`는 별도 provider class가 아니라 `type: "openai-compatible"` preset으로 동작한다.
- OpenRouter API key는 저장하지 않고 `OPENROUTER_API_KEY` 환경변수에서만 읽는다.
- 기본 정책에서 `openrouter`는 disabled로 둔다.
- OpenRouter model id는 사용자가 `POLICY.json`에서 명시한다.
- OpenRouter preset은 기본 `responseFormat: "json_object"`를 사용하되, 호환성 문제가 있으면 `null`로 끌 수 있다.

## Key Changes

- `POLICY.json` provider config에 `type`, `responseFormat`, `extraHeaders`를 추가한다.
- OpenRouter preset:
  - `baseUrl: "https://openrouter.ai/api/v1"`
  - `endpointPath: "/chat/completions"`
  - `apiKeyEnv: "OPENROUTER_API_KEY"`
  - disabled by default
- `createProvider()`는 provider id가 아니라 config `type` 기준으로 provider class를 선택한다.
- `OpenAICompatibleProvider`는 instance id를 받아 `openrouter`로 표시될 수 있다.
- 필수 헤더 `Authorization`, `Content-Type`은 `extraHeaders`보다 최종 우선권을 가진다.
- `responseFormat`이 truthy일 때만 request body에 `response_format`을 포함한다.

## Test Plan

- `policyConfigSchema`가 OpenRouter preset을 파싱한다.
- 기존 v0.15 policy는 provider `type`과 OpenRouter preset을 repair한다.
- `createProvider("openrouter")`가 `OpenAICompatibleProvider`를 생성한다.
- disabled/missing config/missing API key 상태를 명확히 분리한다.
- mocked fetch가 OpenRouter URL, env key, extra headers, safe required header merge를 검증한다.
- `responseFormat: "json_object"`와 `responseFormat: null` body 차이를 검증한다.
- 기존 v0.15 tests 유지.
