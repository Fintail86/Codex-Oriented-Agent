# COSIA v0.57 Plan: Gateway Surface Registry Refactor

## Summary

v0.57 reduces Gateway/Telegram hardcoding by moving slash command metadata, role requirements, help output, callback namespaces, and Telegram Bot API operating defaults into registry/descriptor structures.

Core principles:
- Version is `0.57.0`.
- User-facing Gateway behavior remains compatible.
- Gateway roles stay deterministic: `unknown != guest`, `guest < admin < master`.
- Telegram Bot API compliance constants are centralized, not removed.
- No natural-language command translator is added.
- Slash commands remain the user control surface.

## Key Changes

- Add a `GatewayCommandRegistry` for Gateway slash command metadata.
  - Registered commands include `/help`, `/whoami`, `/status`, `/sessions`, `/jobs`, `/job`, `/cancel`, `/review`, `/pending`, `/apply`, and `/tool grow`.
  - Role and read-only/mutation classification comes from registry metadata.
  - Gateway help is generated from the registry.

- Add a minimal `GatewayConnectorDescriptor`.
  - Telegram is the first descriptor.
  - Descriptor fields cover connector id/name, addressed command normalization, bootstrap hints, callback namespaces, and message defaults.
  - Telegram-specific fields cover long polling, webhook conflict policy, Bot API `allowed_updates`, and retry-after behavior.

- Centralize Telegram Bot API operating defaults.
  - `allowed_updates` remains `["message", "callback_query"]`.
  - Empty `allowed_updates` is not sent.
  - Send pacing, typing refresh, and chunk size are read through descriptor/config settings.

- Route Telegram callbacks by namespace/action.
  - Review callbacks are parsed as callback actions instead of first converting to slash command strings.
  - Unknown callbacks return a short notice and create no mutation.

- Keep legacy Telegram auth compatibility isolated.
  - Legacy fields still read for compatibility.
  - New writes continue to use canonical `gateway.authorization`.
  - Removal of legacy read fallback remains a later wave.

## Test Plan

- `npm run typecheck`
- `npm test`
- `npm run build`
- `node dist/src/bin.js gateway status`
- `node dist/src/bin.js gateway telegram check`
- `node dist/src/bin.js policy check`
- `node dist/src/bin.js config check`

Additional scenarios:
- Gateway help is generated from registry and keeps existing command lines.
- Admin read-only and master mutation role boundaries remain unchanged.
- Unknown users are blocked before provider calls except `/whoami`.
- Telegram callback parsing uses descriptor namespace/action allowlists.
- Telegram `getUpdates` sends `allowed_updates: ["message", "callback_query"]`.
- Secret/token/raw prompt/raw provider payload never appears in Gateway output.

## Assumptions

- v0.57 is a structure refactor, not a feature expansion.
- Telegram remains the only implemented connector.
- `#` command shortcuts remain removed.
- Deprecated Telegram aliases are not removed in this version.
