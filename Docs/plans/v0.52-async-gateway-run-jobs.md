# COSIA v0.52 Plan: Asynchronous Gateway Run Jobs

## Summary

v0.52의 목표는 Telegram/Gateway 요청을 동기식 `runSession` 호출에서 분리해, 사용자가 provider/tool loop 응답을 기다리는 동안에도 상태 확인, 취소, pending 확인, 새 요청 입력을 계속 할 수 있게 만드는 것이다.

## Key Changes

- 버전은 `0.52.0`.
- `RunJob` ledger를 추가한다.
- 상태: `queued`, `running`, `waiting_for_provider`, `waiting_for_tool`, `waiting_for_approval`, `succeeded`, `failed`, `cancelled`, `interrupted`.
- Telegram 자연어 메시지는 RunJob으로 enqueue하고 즉시 접수 응답을 보낸다.
- 같은 session의 job 실행은 concurrency=1로 유지한다.
- `/jobs`, `/job <job-id>`, `/cancel <job-id>`, `/pending`, `/status`는 worker 실행 중에도 처리한다.
- running cancel은 kill 보장이 아니라 cancel request 기록과 final Telegram response suppress를 의미한다.
- gateway stop/restart 중 running/waiting job은 `interrupted`로 기록한다.

## Public UX

```text
작업을 시작했어.
Job: job_xxxxxxxx
상태 보기: /job job_xxxxxxxx
취소: /cancel job_xxxxxxxx
```

## Test Plan

- Telegram 일반 메시지는 즉시 job을 생성하고 접수 응답을 보낸다.
- same-session jobs are processed in order.
- queued cancel prevents execution.
- running cancel records `cancelRequestedAt` and suppresses final response.
- gateway stop/restart marks active jobs interrupted.
- typing heartbeat failure does not fail the job.
- provider final timeout with useful tool result sends deterministic fallback.

## Assumptions

- v0.52 is Telegram/Gateway first.
- CLI `run` and local REPL remain synchronous.
- multi-job parallelism and resume are future work.
