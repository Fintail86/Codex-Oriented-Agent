# COSIA v0.31 Plan: Deterministic Capability Proposal Planner

## Summary

v0.31 creates abstract `CapabilityProposal` records from generic workspace facts and user requests. This is a deterministic planner-only version with no shell approval creation, tool candidate creation, active registration, or LLM planner.

## Key Decisions

- `capability plan --request` does not auto-create a scan.
- Planner requires a latest valid scan; stale or missing scans produce rescan guidance.
- Default stale threshold is `maxStaleAgeMs = 300000`.
- Proposal records store creation-time `sourceScanId`; it is not a dynamic latest-scan pointer.
- User-request-only evidence cannot produce `confidence: high`.
- The deterministic planner is a capability-family normalizer, not a concrete tool keyword detector.
- Requests mentioning Git/NPM/Python/Bun are normalized to abstract families such as `change_tracking`, `project_check`, or `runtime_execution`.
- No concrete command string, runner, or command-like phrase is stored in proposal text.
- `recommendedNextStep = shell_preview` is only a next-step marker; v0.31 creates no shell approval rows.
- Missing grounding fact ids are silently pruned; empty hypotheses/approaches are removed.
- If all hypothesis/approach evidence is pruned, the proposal becomes `ignored`.

## Public Interfaces

- `cosia capability plan --request "<text>"`
- `cosia capability review [--all]`
- `cosia capability show <id>`
- `cosia capability discard <id> --reason "<reason>"`
