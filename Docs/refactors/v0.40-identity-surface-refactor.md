# v0.40 Identity Surface Refactor

## Goal

Align COSIA's public wording, README, CLI description, and top-level docs with the new identity:

```text
COSIA is a lightweight, provider-neutral agentic runtime guided by a user-amendable Codex.
```

## Why This Stage Exists

COSIA has accumulated powerful subsystems, but its visible identity can still read like an experimental self-improving tool or a Codex CLI clone. This stage makes the product shape clear before deeper refactors begin.

## Current State

- Architecture docs now define the user-amendable Codex direction.
- README and CLI help are the primary surface that must stay aligned with the identity wording.
- Some docs may still imply default provider assumptions or Codex CLI dependency.
- Architecture docs should preserve the narrowed hard-deny phrase: `secret persistence outside approved private secret storage`.

## Intended End State

- README and CLI root description use the new COSIA identity.
- Docs explain `Codex-Oriented` as user-amendable `codex/` law, not provider lock-in.
- Normal, advanced, and debug UX categories are documented.
- Private secret storage remains allowed when explicitly approved and routed through the private secret store.

## In Scope

- README wording.
- CLI root description/help wording.
- Architecture doc wording fixes.
- Links from README or docs to identity/refactor phase docs.
- Documentation-only classification of normal/advanced/debug surfaces.

## Out Of Scope

- Command behavior changes.
- CLI command removal or alias removal.
- Provider onboarding implementation.
- Codex amendment implementation.
- Any config, policy, test, or runtime behavior change.

## Implementation Plan

- Update README introduction to describe COSIA as a user-amendable Codex based runtime.
- Update CLI root description to avoid "MVP" framing.
- Replace wording that implies Codex CLI is required or default.
- Clarify that provider profiles are the normal brain selection path.
- Preserve the narrowed `secret persistence outside approved private secret storage` hard-deny wording.
- Add a short normal/advanced/debug UX summary to docs, not to every command help screen.

## Public UX / CLI Impact

- Help text wording changes only.
- No command names, flags, behavior, or output data shape changes.
- Users should understand COSIA as a lightweight runtime rather than a configuration-heavy experiment.

## Data / Config / Policy Impact

- No schema change.
- No migration.
- No policy JSON change.
- No runtime config change.

## Risks And Guardrails

- Do not over-edit historical plan files; add supersession notes instead.
- Do not imply Codex law Markdown is the only security boundary.
- Do not call COSIA an OpenAI Codex CLI clone.
- Do not remove advanced commands in this stage.

## Test Plan

- Run `git status --short --ignored`.
- If package metadata, version strings, or CLI help text are changed, run:
  - `npm run typecheck`
  - `npm test`
  - `npm run build`
  - `node dist/src/bin.js --help`

## Acceptance Criteria

- README and CLI description use the new identity language.
- Identity docs do not conflict with private secret store behavior.
- Provider lock-in/default-provider wording is removed from current-facing docs.
- No runtime behavior changes are included.
