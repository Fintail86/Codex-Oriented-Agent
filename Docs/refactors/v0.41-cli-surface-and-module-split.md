# v0.41 CLI Surface And Module Split

## Goal

Reduce `src/cli.ts` responsibility by moving command groups into focused modules while preserving command behavior.

## Why This Stage Exists

The CLI is currently the main public surface and a large implementation hub. It needs structural separation before UX simplification, alias removal, or command grouping changes can be safely made.

## Current State

- Provider profile commands have already been extracted.
- Other command groups remain mixed in `src/cli.ts`.
- Deprecated aliases still exist and should not be removed during structural splitting.
- Normal/advanced/debug categories are documented but not yet reflected in CLI implementation boundaries.

## Intended End State

- `src/cli.ts` is an assembler for top-level command groups.
- Command groups are registered by focused modules.
- User-visible command behavior remains stable.
- Deprecated aliases remain available until a dedicated removal stage.

## In Scope

- Gateway/Telegram command module extraction.
- Tool growth and tool acquisition command module extraction.
- Memory/session command module extraction.
- Policy/config command module extraction.
- Help text grouping preparation where it does not change command semantics.

## Out Of Scope

- Alias removal.
- Command renaming.
- Command output redesign.
- Provider onboarding behavior changes.
- Tool growth behavior changes.
- Memory data model changes.

## Implementation Plan

- Extract one command group per commit or small PR.
- Start with gateway/Telegram because connector setup is actively used.
- Move tool growth/tool acquisition after gateway command extraction.
- Move memory/session after tool commands.
- Move policy/config last because they are cross-cutting.
- Keep command registration tests passing after each extraction.

## Public UX / CLI Impact

- Command names and flags stay the same.
- Help output should remain equivalent unless a wording-only change is explicitly included.
- No deprecated alias is removed.

## Data / Config / Policy Impact

- No schema change.
- No migration.
- No policy change.

## Risks And Guardrails

- Do not mix behavior changes into module extraction.
- Do not change command_adapter runtime behavior.
- Do not remove compatibility paths.
- Do not reorganize tests and implementation in the same large commit unless the test move is purely mechanical.

## Test Plan

- `npm run typecheck`
- `npm test`
- `npm run build`
- CLI smoke tests for extracted groups:
  - `cosia provider profile list`
  - `cosia gateway telegram list`
  - `cosia tool active list`
  - `cosia memory review`
  - `cosia session list`
  - `cosia config check`

## Acceptance Criteria

- `src/cli.ts` is smaller and primarily assembles command modules.
- Extracted command groups preserve behavior.
- Existing tests pass.
- No deprecated alias is removed.

## Follow-Up Work

- Later phases may revise help grouping and deprecate aliases after module boundaries are stable.
