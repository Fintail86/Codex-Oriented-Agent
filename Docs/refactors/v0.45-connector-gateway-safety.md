# v0.45 Connector Gateway Safety

## Goal

Harden Telegram and future gateway connectors as COSIA's external body, with special attention to group chat safety.

## Why This Stage Exists

Connectors expose COSIA outside the local CLI. A connector can amplify mistakes if authorization, mutation approval, or provider ownership boundaries are unclear.

## Current State

- Telegram supports enable/set/check/start style setup.
- Telegram connector does not own provider selection.
- Authorization is primarily chat-id based.
- Group chat behavior needs user-level safety before mutation-capable use is comfortable.

## Intended End State

- Connector config follows the `enable/disable/set/unset/list/check` contract.
- Telegram has `/whoami` / `#내 정보` chat/user identity discovery.
- Group chats are read-only by default unless explicitly upgraded.
- Mutation approvals are limited to configured mutation user ids.
- Gateway status/check/repair commands help users recover without editing files manually.

## In Scope

- Connector CLI contract documentation and tests.
- Telegram chat allowlist and user allowlist design.
- Admin-only mutation design.
- Group read-only default.
- `/whoami` or equivalent chat/user id discovery.
- Gateway stale lock and state repair UX.

## Out Of Scope

- Moving provider selection into gateway config.
- Allowing group mutations without user-level authorization.
- Adding unrelated connectors before Telegram safety is settled.
- Making plain group conversation auto-execute runtime commands.

## Implementation Plan

- Define connector authorization layers:
  - connector enabled
  - chat allowed
  - user allowed
  - mutation allowed
  - admin mutation allowed
- Add discovery UX for chat id and user id.
- Add `allowedUserIds`, `mutationUserIds`, and `groupMode` to Telegram connector config.
- Make group chat default read-only until configured with `groupMode=allowed_users`.
- Require explicit mutation approval from configured `mutationUserIds`.
- Keep `#` and slash runtime commands distinct from ordinary group conversation.
- Ensure gateway check and gateway start share token/config resolvers.

## Public UX / CLI Impact

- Telegram setup remains simple for one-to-one chat.
- Group setup requires explicit safety configuration.
- Users can discover the correct ids from CLI or Telegram command flow.
- New Telegram config commands:
  - `cosia gateway telegram set user-id <user-id>`
  - `cosia gateway telegram set mutation-user-id <user-id>`
  - `cosia gateway telegram set group-mode read-only|allowed-users`
- Gateway errors should include exact recovery commands.

## Data / Config / Policy Impact

- Adds Telegram connector user allowlist and group mode fields with safe defaults.
- Telegram token remains in private secret storage or env.
- Provider profile remains outside connector config.

## Risks And Guardrails

- Do not let any group member approve mutations by default.
- Do not print Telegram tokens or secrets.
- Do not let connector config select the model provider.
- Do not auto-repair stale gateway state in a way that hides data loss.

## Test Plan

- One-to-one Telegram flow remains working.
- Group chat without user allowlist is read-only or mutation-denied.
- Authorized user can perform allowed mutation flow.
- Unauthorized user cannot apply pending mutation.
- `/whoami` or equivalent reports ids without leaking secrets.
- Gateway stale lock repair guidance remains clear.

## Acceptance Criteria

- Telegram group usage has a documented safe path.
- Connector authorization is layered.
- Gateway provider selection remains profile-owned.
- Gateway recovery is possible from CLI.

## Follow-Up Work

- Future connectors should reuse the same connector contract and authorization model.
