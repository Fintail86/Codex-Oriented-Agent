# v0.44 Memory Session Debug UX

## Goal

Clarify and simplify the UX for session context, session summaries, long-term memory, and debug prompt records.

## Why This Stage Exists

COSIA owns continuity, but multiple memory-like concepts can confuse users and maintainers. This stage makes each layer's purpose explicit and improves inspection/recovery flows.

## Current State

- `CONTEXT_MEMORY.md` stores recent run history.
- `SESSION_SUMMARY.md` stores compact continuity.
- Long-term memory uses candidate/review/promotion flows.
- Debug files now store the last user message and last prompt.
- Commands expose pieces of this model, but the conceptual boundary is not yet polished.

## Intended End State

- Users can tell which memory layer they are inspecting.
- Session context is treated as working context, not durable truth.
- Long-term memory is promoted and reviewable.
- Debug prompt/user-message files are clearly diagnostic, not user memory.

## In Scope

- Documentation and CLI wording for memory layers.
- `cosia session debug <session-id>` for last-turn metadata, user message, prompt, or all parts.
- Context compact/summarize UX cleanup.
- Memory review/promote/conflict guidance.
- Status output that distinguishes context health from long-term memory health.

## Out Of Scope

- Replacing the memory storage engine.
- Automatic aggressive memory promotion.
- Deleting existing memory data.
- Collapsing debug files into memory.

## Implementation Plan

- Document four memory layers:
  - session context: `CONTEXT_MEMORY.md` recent working history
  - session summary: `SESSION_SUMMARY.md` compact continuity
  - long-term memory: reviewed/promoted durable memory records
  - debug records: `debug/LAST_TURN.json`, `debug/LAST_USER_MESSAGE.md`, and `debug/LAST_PROMPT.md`
- Add `cosia session debug <session-id>` with:
  - `--part metadata`
  - `--part user-message`
  - `--part prompt`
  - `--part all`
  - `--max-chars <n>` for large prompt/user-message output
- Refine existing output labels for:
  - `session show`
  - `session context status`
  - context compact blocked guidance
  - `status`/`doctor` wording where long-term memory and working context can blur together
- Keep debug records under session-local `debug/`.
- Make context compaction guidance clearer when summary is placeholder.
- Ensure prompt/debug records are not promoted to long-term memory automatically.

## Public UX / CLI Impact

- Users get clearer wording about what is remembered.
- Debug inspection becomes easier without reading raw session folders manually.
- No normal chat behavior changes are required.

## Data / Config / Policy Impact

- No required schema change.
- Existing session files remain compatible.
- Debug files remain runtime artifacts and are not tracked or staged.

## Risks And Guardrails

- Do not treat `CONTEXT_MEMORY.md` as durable fact memory.
- Do not promote secrets or raw debug prompts into memory.
- Do not remove existing compact/undo safety behavior.
- Do not make debug files normal UX noise.

## Test Plan

- Context status still reports warning/critical thresholds.
- Compact preview/apply behavior remains stable.
- Last prompt debug files are written on run.
- `session debug` reports a clear message when no debug record exists.
- `session debug --part metadata` shows run id, model step, prompt chars, and estimated tokens.
- `session debug --part user-message` shows `LAST_USER_MESSAGE.md`.
- `session debug --part prompt --max-chars <n>` caps `LAST_PROMPT.md` output with a truncation marker.
- `session debug --part all` shows metadata/user-message/prompt with prompt cap applied.
- Debug inspection command never reads outside the session-local debug path.
- Memory review tests continue passing.

## Acceptance Criteria

- Documentation and CLI wording distinguish memory layers.
- Users can inspect recent prompt/debug data without confusing it with long-term memory.
- Existing memory/session behavior remains compatible.

## Follow-Up Work

- Evidence lifecycle and cold storage can reuse the same conceptual separation.
